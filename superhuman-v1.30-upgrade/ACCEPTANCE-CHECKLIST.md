# Owner acceptance after installation

1. Sign in and open Settings > System baseline. Check the installed release, worker heartbeat, team activation, model/rate-card configuration, last historical model response and channel sync evidence. An unverified label is not a failure invented by the installer; it means evidence has not been observed. A paused worker stays paused.
2. Open The Twin. Her name should be The Twin, with Superhuman shown as her title. Open Team > Personalities and inspect all eight styles. Change one, reload and verify it persists. Personality edits do not authorize actions or train model weights.
3. Open Storage. Verify seven department folders and Shared facts. Existing source files should appear under their owning department as awaiting registration; they are not automatically approved or shared.
4. Upload a test source or register an existing one. Set its source, project if applicable, tags, sensitivity, review date and named recipients. Approve only after review. Reusing an existing filename must not overwrite the file.
5. Preview retrieval as the owning agent and an agent without access. A confidential item must not appear under an internal sensitivity ceiling. A project-only item should require that project's ID.
6. For a non-sensitive test fact, use a stable key, source and explicit Twin access. Ask a matching question in The Twin chat. Check the selected source version in the saved turn context trace. Project chats remain project-scoped.
7. Set a review date in the past or change a test file outside Storage. Retrieval should exclude its content and show a review warning. Reconfirm the updated source to save a new metadata version. Previous metadata and hashes remain in version history; the catalogue does not archive overwritten file bytes.
8. Create two approved test facts with the same key but different values and overlapping access. Retrieval should withhold both values and identify the conflict. Archive the outdated record to resolve it.
9. Open Settings > Proactive checks, run a local scan and inspect a test deadline/empty-project signal. Repeated scans should not duplicate it. Acknowledge it; acknowledgement must survive rescans. Resolve and recreate the underlying condition to check reopening.
10. Review each rule before changing Notify to Twin review. Twin review can use existing paid coordinator calls when the team/worker and existing allowance permit. It cannot grant permissions, bypass owner approvals or send anything externally.
11. Review EXTERNAL-ACTIONS-PROPOSAL.md before authorizing future external-action work.

Do not use the synthetic test fixtures as your business data. This package contains no owner documents, credentials, registry replacement or connected account sessions.
