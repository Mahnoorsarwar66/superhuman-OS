# Architecture through v1.34

Mahnoor retains strategic authority. The department specialist leads the project. The Twin supervises internal work. Existing specialist task, milestone, evidence and exact-packet approval workflows remain authoritative.

## Project interview lifecycle

New managed project -> enrolled draft -> four essential initial answers plus optional deeper context -> explicit owner confirmation -> execution under existing controls. Changes to saved answers or project controls hold future work pending reconfirmation. Department-specific prompts and scoped specialist questions extend the interview. Proposed unanswered questions do not change confirmed scope. Answered clarifications change the version and hold affected work until reviewed.

Draft answers never enter employee context. Confirmed answers require project-roster membership and an adequate sensitivity ceiling. Owner answers remain reference data, not tool permissions or independently verified evidence. Interview fingerprints enter enrolled-project quality review scope so an old scorecard cannot silently approve a changed brief. Historical approvals remain historical.

Initial discovery is possible after a short confirmed brief while deeper unknowns remain explicit. This release does not run an autonomous interviewer before that brief or bypass task/source controls to research private information. Existing projects require deliberate enrolment; unmanaged historical runs keep their current controls.

## Execution and progression

One existing persistent worker, existing metered calls and existing budget reservations. The optional ready-milestone action calls the established start function; it does not create a second scheduler, approve dependencies, confirm requirements, grant source access or reset spending ceilings. The team must be enabled and budget-ready; current project/employee/criteria/requirement/dependency/source/hold controls remain effective.

Internal project.interview proposals extend the existing team collaboration permission for employees already allowed to propose memory. Setup records the change once; it does not grant outbound permissions. Questions are derived from the actual assigned run, never a model-supplied actor or project ID. No new channel connection or external action tool is included.

General operating decisions are provided as scoped task/review instructions and a visible operating guide. Semantic judgment, initiative quality and communication discipline require live evaluation; instructions are not deterministic correctness guarantees.

## Evidence and business value

Existing v1.32 evidence/requirement/quality gates remain. New impact reviews require the current owner-approved packet and pin its ID/digest. They are explicit owner assessments, not automatically measured or independently certified results. Accepted deliverables, readiness changes and observed outcomes stay separate.

Assignment charges include attempts and revisions across periods. Milestone coordination receives a project attribution link inside the existing atomic reservation. No budget mathematics or rate card is replaced. Older unallocated calls and shared overhead cannot be reconstructed reliably. Time and monetary ranges require owner inputs; elapsed weeks alone do not establish saved working hours.

## Interface and documents

Local CSS adds a coherent task-focused visual hierarchy without replacing existing business handlers. Native forms, labels, fieldsets and progress links work without JavaScript. Dictation is optional browser enhancement and never submits. Eight generated fictional portraits are authenticated local assets.

PDF/Word exporters reuse the existing export registry/source provenance and support native tables, headings, bullets and page numbers. No financial spreadsheet model, OCR, advanced page designer or final-business-document certification is introduced.

## Migration and rollback

Exact v1.33 source guards, staged regression, protected CLI/orchestrator variants, private backup, atomic source writes and per-file manifests. New schema is additive. Installation does not enrol existing projects or create paid work. Rollback restores previous source, removes the interview tool permission, pauses affected runs and the worker, and preserves data/history. The previous application does not enforce new interview gates; inspect before resuming.
