# Team acceptance checklist

- [ ] Team opens one balanced workspace; desktop and mobile navigation remain usable.
- [ ] All eight employee portraits appear without a legacy bot overlay; employee cards show actual work and worker availability separately.
- [ ] Clicking an employee continues a stable primary direct chat. Earlier messages, microphone, drafts, reply limits, cancel and retry controls remain available.
- [ ] Find a word appearing only inside a message. Open its exact anchored message, including older pages.
- [ ] Rename, pin, archive and restore a conversation. Archived rooms refuse new messages. Mark read, then verify a new saved reply creates new activity.
- [ ] Create a project channel from approved project leadership and sharing; confirm only rostered employees are offered.
- [ ] Create a milestone thread. Ask one employee a question, then ask the lead to obtain relevant specialist input and integrate the real replies.
- [ ] Confirm that no unnecessary all-agent response occurs. Check recorded attempt and dollar limits.
- [ ] Pause an employee or revoke sharing before a queued reply: stale/revoked context must not be committed.
- [ ] Inspect Working context. Correct an owner-confirmed note and verify later replies use that version.
- [ ] Upload a document as a draft; approve exact source/access in Storage; link it. A changed/revoked source must require review and relinking.
- [ ] Inspect source-backed project assignments and handoffs inside the channel.
- [ ] Review an exact work card. Check owner, criteria, date, classification and milestone. Authorize manually or request routine Twin review.
- [ ] Test optional routine-review delegation in a noncritical channel after a successful manual review. Consequential or restricted work must remain for the owner.
- [ ] Verify authorized work enters the existing governed task/milestone pipeline. A discussion or Twin card approval must not approve the milestone output or authorize external sending.
- [ ] Inspect Needs your attention, actual owner mentions and saved review decisions.

Use a small real pilot after these software checks; model competence and business value require actual observed outputs.
