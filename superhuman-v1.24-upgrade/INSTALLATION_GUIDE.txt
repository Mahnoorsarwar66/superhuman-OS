SUPERHUMAN OS v1.24 — INSTALLATION

Prerequisite: the delivered v1.23 repair release installed at
/home/superhuman/app. The installer checks exact prior Python structure and
refuses unfamiliar source before overwriting anything. No pip upgrade, database
replacement, credential change, Nginx change or service-unit rewrite is needed.
Keep the existing server environment and specialist registry.

1. Download and extract the ZIP into C:\superhuman-os-starter.
   Confirm this exact file exists:
   C:\superhuman-os-starter\superhuman-v1.24-upgrade\upgrade_server.sh
   If the extractor creates a second nested folder, move the inner upgrade folder
   to that path. Do not copy the ZIP itself to the app source directory.

2. Run in Windows PowerShell:

scp -r -o IdentitiesOnly=yes -i "$env:USERPROFILE\.ssh\superhuman_replacement" "C:\superhuman-os-starter\superhuman-v1.24-upgrade" superhuman@167.71.196.20:/home/superhuman/
ssh -o IdentitiesOnly=yes -i "$env:USERPROFILE\.ssh\superhuman_replacement" root@167.71.196.20

3. In the Ubuntu SSH session:

chown -R superhuman:superhuman /home/superhuman/superhuman-v1.24-upgrade
bash /home/superhuman/superhuman-v1.24-upgrade/upgrade_server.sh

The script preflights source/dependencies, stops web and worker, writes a private
full backup, runs the whole suite against a temporary source copy without live
data or model credentials, backs up changed code, installs and restarts services.
If checks fail, source is retained and services restart. The script prints the
code rollback directory; retain that exact path. The full private backup may
contain sensitive information and stays under private-backups with mode 700.

4. Open https://superhuman.167-71-196-20.sslip.io/
   Refresh and open Tasks > Agent runs. Settings > System checks and /healthz
   report 1.24.0. Diagnostics include saved agent run states and spend no requests.

ROLLBACK (Ubuntu as root; replace the timestamp with the printed backup path):
bash /home/superhuman/superhuman-v1.24-upgrade/rollback_server.sh /home/superhuman/app/backups/v1.24-TIMESTAMP

Source checksums must still match. User data/artifacts are retained; global
background work stays paused. Unfinished agent tasks become unavailable and their
projects are held. Reinstall v1.24, inspect them, then use Agent runs continuation
controls before resuming the global worker. Do not turn them into legacy jobs.
Completed deliverable records are retained. Their review controls become available
after reinstall/startup; rollback temporarily quarantines every agent task. Code rollback does
not undo already-created files, coding-copy edits, notes or internal objectives.
